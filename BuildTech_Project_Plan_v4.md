## 1. Product Positioning

BuildTech is a local-first, single-user desktop application whose **single central output is a candidate portfolio**.

Everything else exists to serve this output:
- **Screening** → narrows the universe before construction
- **Scoring** → ranks assets the constructor will consume
- **Watchlist** → an optional personal filter, not a required path
- **History** → preserves past constructions for revisit and comparison

**Is:** portfolio construction assistant with explainable inputs and outputs.

**Is not:** screener, signal generator, robo-advisor, trading platform, or advice product.

**Language discipline:**
✅ candidate portfolio, model allocation, historical avg return, illustrative scenario, screening result, decision-support output, suggested allocation

❌ recommended investment, you should buy, optimal guaranteed, profitable signal, beat the market

❌ **Forecasting/predictive language is banned product-wide:** *expected return*, *projected*, *forecast*, *predicted*, *anticipated performance*. Where past-data summaries are needed, use *"historical average X over period Y"* with the window stated.

## 3. Hard Locks (Non-Negotiable for v1.0)

### Data Source Lock
**v1.0 uses yfinance and only yfinance.** No Tiingo, IEX Cloud, Alpha Vantage, ECB, FRED, FMP, SimFin, or any other source — even for "small enhancements." Adding any new source requires a v1.1+ RFC.

Exception path (v1.1 only): CoinGecko for crypto. Anything else needs an explicit architectural decision record (ADR).

### Construction Algorithm Lock
**Portfolios are always generated by the construction algorithm at request time.** Hardcoded portfolios, sample allocations baked into code, or "demo portfolios" stored as constants are **prohibited in production code paths**. Test fixtures may contain reference portfolios but must be:
- Located only under `tests/` or files suffixed `_test_only`
- Never imported by `app/api/*` or `app/core/construction.py`
- Marked with module-level `# TEST FIXTURE — NOT FOR PRODUCTION USE`

Every persisted portfolio carries `generation_method` metadata (required, validated): `"risk_parity_full" | "risk_parity_relaxed_N" | "equal_weight_fallback"`. No portfolio can be saved without this field.

### Forecasting Language Lock
Build-time lint rule (or pre-commit hook) flags forbidden terms in source files and UI strings: `expected return`, `forecast`, `predicted`, `projected`, `anticipated`. Documentation may reference these only in §1's forbidden-list.

## 6. Asset Scoring — With Factor Source Matrix

### Stocks (composite 0–100)

| Factor | Weight | **Source** | Refresh trigger |
|---|---|---|---|
| Value (P/E, P/B, EV/EBITDA, FCF Yield) | 25% | **Fundamentals snapshot** | Weekly script |
| Quality (ROE, ROIC, D/E, Margin stability) | 25% | **Fundamentals snapshot** | Weekly script |
| Momentum (3M/6M/12M return vs 200-day MA) | 20% | **Price cache** | Manual price refresh |
| Volatility-adjusted (Sharpe, Sortino, Beta-adj return) | 15% | **Price cache** (+ FRED rf rate from snapshot) | Manual price refresh |
| Size/Liquidity (Market cap, ADV) | 15% | **Mixed** (mcap from fundamentals; ADV from prices) | Both |

### ETFs (composite 0–100)

| Factor | Weight | **Source** | Refresh trigger |
|---|---|---|---|
| Cost (expense ratio) | 20% | **Fundamentals snapshot** | Weekly script |
| Liquidity & AUM | 25% | **Fundamentals snapshot** (AUM) + Price cache (ADV) | Both |
| Risk-adjusted return | 30% | **Price cache** | Manual price refresh |
| Diversification benefit | 25% | **Price cache** (correlation to broad market) | Manual price refresh |

### Implications
- A **price refresh** triggers re-computation of: Momentum, Vol-adjusted, Risk-adjusted return, Diversification, ADV component of Size/Liquidity. Final composite is recombined with cached fundamentals sub-scores.
- A **fundamentals snapshot run** triggers re-computation of: Value, Quality, Cost, AUM. Recombined with cached price-based sub-scores.
- Neither refresh ever calls the other's source.
- Each cached score row records both `fundamentals_snapshot_date` and `prices_computed_at` so partial-recompute is correct and traceable.

### Transparency
- Click score → breakdown shows each sub-factor with its source label (📈 Fundamentals / 📊 Prices) and freshness for that source
- N/A handling: missing sub-factor excluded, remaining re-normalized; composite displays `*`; tooltip explains which factor is missing and why

## 7. Portfolio Construction (Central Output)

### Source Behavior
Builder always operates on a **source pool**:
- **Default:** Full Universe (entire scored S&P 500 + NASDAQ 100 + ETF list)
- **Optional toggle:** Watchlist (uses only watchlist tickers as candidate pool)

The toggle is in Builder UI top bar. Watchlist mode is never default.

### 3 Variants
- **Core** — risk-level-centered, balanced across factors
- **Growth Tilt** — re-weights composite toward Momentum + growth-quality stocks and growth-oriented ETFs
- **Defensive Tilt** — re-weights composite toward Volatility-adjusted, dividend/quality stocks, broad-market ETFs

### Algorithm
1. **Filter** source pool by risk-level constraints (vol ceiling, min liquidity, asset class %)
2. **Re-rank** by variant-adjusted composite (Growth/Defensive shift sub-factor weights ±10%)
3. **Select** top-N via greedy correlation-aware selection (see §10)
4. **Allocate** via Risk Parity within class, then class-level weights from risk profile
5. **Apply constraints**: single asset max 20%, class min/max, 8–20 positions total
6. **Output** 3 variants, each with: holdings, weights, sub-score breakdowns, skip log, construction log

### Construction Log (Per Variant)
Every construction produces a `construction_log` — an ordered list of events persisted with the portfolio:
```
[
  {step: "filter", input_count: 630, output_count: 412, reason: "vol_ceiling=0.18, min_adv=1M"},
  {step: "rank", method: "variant_adjusted_composite", variant: "growth_tilt"},
  {step: "select", target_n: 15, selected: 12, skipped: 8},
  {step: "allocate", method: "risk_parity", status: "success"},
  {step: "constraints", violations: 0}
]
```

If Risk Parity fails:
```
{step: "allocate", method: "risk_parity", status: "infeasible"},
{step: "allocate_retry", method: "risk_parity", relax_step: 1, status: "infeasible"},
{step: "allocate_retry", method: "risk_parity", relax_step: 2, status: "success"}
```

Or full fallback:
```
{step: "allocate_fallback", method: "equal_weight_clipped", reason: "risk_parity_infeasible_after_3_relaxations"}
```

This log is **visible in the UI** (collapsible "How this portfolio was built" panel) and **included in every export**.

## 9. Data Architecture

### Two Tracks
| Track | Source | Strategy | Refresh |
|---|---|---|---|
| **Prices** | yfinance | 3-tier: live → SQLite cache → frozen parquet | Manual button |
| **Fundamentals** | yfinance via weekly script | Snapshot-only, never live in app | `scripts/refresh_fundamentals.py` |

### Prices: 3-Tier Resolution
```
Request → Live yfinance → fail → SQLite cache (<24h) → miss → Frozen parquet snapshot
```

### Fundamentals: Snapshot-Only
- App never calls yfinance for fundamentals at runtime
- Script writes `backend/snapshots/fundamentals_YYYY-MM-DD.parquet`
- Symlink `fundamentals_latest.parquet` always points to most recent
- Keep last 4 weeks, prune older
- Per-ticker partial failure tolerated up to 10%; logged
- Idempotent within a day; end-of-run summary report

### Dual Freshness UI
- **📊 Prices:** 🟢 Live / 🟡 Cached / 🔴 Snapshot — `Last refresh: 2h ago` — `↻ Refresh Prices` button
- **📈 Fundamentals:** `Updated 3d ago` — green <7d, amber 7–14d, red >14d — no in-app button (script is manual)

## 10. Correlation-Aware Selection

### Thresholds (default, in `config.py`)
| Pair | Threshold | Window |
|---|---|---|
| Stock ↔ Stock | 0.80 | 1Y daily returns |
| ETF ↔ ETF | 0.75 | 1Y daily returns |
| Stock ↔ ETF | 0.85 | 1Y daily returns |

### Algorithm
Greedy: highest-scored asset enters first; each subsequent candidate must satisfy `corr < threshold(class_pair)` with all already-selected. Skips are logged with reason.

### Edge Case
If selection ends with <8 assets: relax all thresholds by 5% (max 3 relaxations). If still <8 → return what was selected + `insufficient_diversification` warning + relaxation count in construction log.

### Persistence
Skip events are persisted to `portfolio_skip_log` (see §12) and surfaced in UI:
> *"AAPL skipped — correlation 0.82 with MSFT (already selected), threshold 0.80"*

## 11. Watchlist & Saved Portfolios

### Watchlist
- Single user, single list
- Optional Builder source filter; never default
- Persisted in SQLite
- Add from Universe Explorer or detail drawer; remove from Watchlist page

### Saved Portfolio Lifecycle

| Status | How it enters | Visibility | Behavior |
|---|---|---|---|
| **Draft** | Auto-saved on Builder customization (debounced 2s) | Hidden from History default view (toggle to show) | Overwritten on next customize; one draft per variant |
| **Saved** | User clicks "Save" explicitly (modal: name confirmation) | Default History view | Immutable holdings/weights; edits create a new Saved portfolio |
| **Archived** | User explicitly archives from History | Behind "Archived" filter | Read-only; can be opened, exported, compared; cannot be promoted back without "Unarchive" action |

History default = Saved only. Filters: All / Saved / Drafts / Archived. Compare-two works across any combination.

## 20. Out-of-Plan Change Process

Anything not in this plan that comes up during development is handled as follows:
- **Small adjustments** (config values, UI polish, bug fixes): proceed, note in commit message
- **Architectural changes** (new module, new dependency, behavior change): require an **ADR** (Architectural Decision Record) committed to `docs/adr/NNNN-<title>.md` before implementation
- **New data sources, asset classes, or scope expansion**: defer to v1.1+ planning cycle; do not implement in v1.0 branch
